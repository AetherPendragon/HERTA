## 核心实现说明

### 1. JSON 比较 (json_compare.py)
- **拓扑相似度**：检查 4 层树结构（根、6个字段、列表元素、元素字段）
- **命令表相似度**：按 cmd 对齐，比较 handler 和 desc（rapidfuzz 模糊匹配）
- **遥测表/内部处理相似度**：按 handler 对齐，比较 len、desc 等字段
- **权重**：topology 20%, cmd_list 30%, tele_handler 30%, internal 20%

### 2. C 代码 AST 解析 (c_ast_parser.py)
- 使用 tree-sitter 解析 C 语法树
- 提取函数名、返回类型、参数列表、函数体源码和 AST
- 支持函数体级别的 AST 比较

### 3. AST 相似度 (ast_similarity.py)
- **树编辑相似度**：使用 apted 算法计算 TED，归一化为 0-1
- **语义特征相似度**：提取调用函数、字面量、赋值模式、标识符、return 模式、控制流，计算 Jaccard 相似度
- **公式**：ast_similarity = 0.70 * tree_edit + 0.30 * semantic

### 4. 函数匹配 (function_matcher.py)
- 构建相似度矩阵（每个真实函数 vs 每个生成函数）
- 使用 scipy.optimize.linear_sum_assignment（匈牙利算法）求解最大权匹配
- 一对一匹配，避免重复占用
- 阈值 0.3，低于此值视为未匹配

### 5. 报告生成 (report_builder.py)
- **metrics.json**：包含 5 个 config 分数、handler 相似度、overall、详细结果
- **comparison_report.md**：结构化报告，分 Config 和 Handler 两部分，包含表格、问题列表、改进建议

## 运行方式示例

```bash
# 安装新依赖
pip install tree-sitter tree-sitter-c apted rapidfuzz scipy

# 使用默认路径
herta compare --target dllg

# 手动指定路径
herta compare --target dllg \
    --gen-config ./output/dllg_config.json \
    --gt-config ./data/target_proto/dllg/dllg_config.json \
    --gen-handler ./output/dllg_handler.c \
    --gt-handler ./data/target_proto/dllg/dllg_handler.c

# 指定输出路径
herta compare --target dllg --report ./reports/compare.md --metrics ./reports/metrics.json
```

## 输出文件

执行完成后在 `output/reports/<target>/` 生成：
- `metrics.json` - 结构化指标
- `comparison_report.md` - Markdown 报告

**metrics.json 包含：**
- topology_similarity, cmd_list_similarity, tele_handler_similarity, internal_handler_similarity
- config_similarity（加权总分）
- handler_similarity（百分制）
- overall_similarity（35% config + 65% handler）
- config_details（详细对比结果）
- function_match_results（函数匹配列表）
- unmatched_gt_functions / unmatched_gen_functions

## 仍可能存在的边界问题

1. **tree-sitter 安装**：某些系统可能需要额外安装编译工具链
2. **apted 依赖**：如果安装失败，会回退到简化树相似度计算
3. **C 语法复杂度**：非常规 C 语法（宏、条件编译）可能解析不完美
4. **大型文件**：超大 C 文件可能导致内存占用较高
5. **相似度阈值**：0.3 的阈值可能需要根据实际数据调整
